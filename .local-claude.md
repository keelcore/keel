# Keel — Project-Local Agent Guidance

Project-local conventions for keel, layered on top of the shared standards in
`.standards/governance/`. The shared standards win on anything they specify; this
file covers keel-specific workflow that the standards do not.

## Coverage Regression Policy — agent duties

Keel enforces the per-file coverage no-regression gate defined in
`.standards/governance/testing.md`. The committed baseline is
`tests/coverage-baseline.lcov`; the gate is `make ci-coverage-no-regression`
(it reads the current LCOV that `make coverage` produces at
`target/coverage/lcov.info`).

Before staging or handing off any change that touches Go source:

1. Run `make coverage`, then `make ci-coverage-no-regression`.
2. If the gate reports a per-file regression, or a new file below the 95% floor,
   DO NOT present the work as complete. Fix or revert until the gate passes, then
   report the affected file(s), the prior and current per-file ratios, and what
   changed. The decision on how to proceed belongs to the human.
3. The baseline moves only as part of a change that holds or increases every
   per-file ratio. When coverage legitimately rises, re-seed with
   `make coverage-baseline-init` and stage the updated
   `tests/coverage-baseline.lcov` in the same change set. When a file is deleted,
   drop its baseline entry in the same change set.

Note on measurement: the gate uses per-module Go line coverage (no `-coverpkg`),
so a file exercised mainly by integration tests in `tests/` shows lower per-file
coverage here than in the aggregate `coverage.txt` report. New files must clear
the 95% floor under this stricter, per-module measure.

This gate runs in CI on every push and pull request — including direct pushes to
`main`, which is where an ungated regression would otherwise slip through.
